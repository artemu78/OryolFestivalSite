# Спонсоры

Раздел `#sponsors` читает `sponsors` из общего ответа действия `list` функции
`festival-admin`. Статического списка и запасного JSON нет.

Таблица YDB **Sponsors** содержит пять обязательных колонок:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | Utf8, первичный ключ | Стабильный UUID, автоматически созданный при импорте |
| `name` | Utf8 | Имя для доступного описания изображения и ссылки; сначала пустая строка |
| `image` | Utf8 | Путь `logos/filename.jpg` либо полный HTTP/HTTPS URL изображения |
| `link` | Utf8 | Полный HTTP/HTTPS URL сайта; сначала пустая строка |
| `display` | Bool | `true` — показывать, `false` — скрыть |

Редактировать строки можно в консоли YDB или через панель администратора на странице `/admin`.
В панели администратора доступен раздел «Спонсоры»: добавление и редактирование выполняются во всплывающем окне (попапе), что позволяет менять название, изображение (выбор из существующих файлов или ввод URL), ссылку и видимость (`display`) без необходимости прокручивать страницу. Также доступно удаление спонсоров и быстрое переключение видимости в списке.

Публичный API возвращает только записи с `display = true`, в порядке `image, id`. Если ссылка пустая, карточка показывает изображение. После заполнения `link` карточка становится ссылкой, открывающейся в новой вкладке. Пустое имя заменяется доступной подписью «Логотип спонсора».

Правки имени, ссылки, изображения и видимости появляются сразу после сохранения в панели управления и обновления данных. Изображения по локальным путям должны уже существовать в опубликованном `logos/`; для нового файла нужна загрузка в бакеты и в GitHub Pages. Внешний URL позволяет использовать новое изображение без изменения сборки.

## Начальный импорт

Таблица описана в `infra/yandex/sponsors.tf`, защищена от удаления и создаётся
до обновления функции. Затем, с операторским окружением из `infra/yandex/README.md`:

```sh
python infra/yandex/seed-sponsors.py
python infra/yandex/seed-sponsors.py --execute
```

Скрипт импортирует все изображения из `public/logos/`, включая три эмблемы
фестиваля, с пустыми `name` и `link`, `display = true`. UUID генерируется
автоматически и стабильно из пути файла. Импорт вставляет только отсутствующие
изображения, сохраняет последующие правки и проверяет результат в одной транзакции.
Повторный запуск не включает обратно скрытые записи и не очищает заполненные поля.
Дубли изображений и конфликт ID прерывают импорт. Другие таблицы не изменяются.

Порядок развёртывания: таблица → импорт → функция → сборка и публикация сайта.
GitHub Pages публикуется отдельно через существующий workflow.
