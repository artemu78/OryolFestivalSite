# Step 3 — Backend and authorization

## Implementation prompt

Update admin/index.py and tests to the identity-schema API contract. Resolve verified VK identity to Users; authorize through UserRoles; return attendee/admin/expert status from me. Never create users or grant roles automatically at login.

Implement user/role/expert-profile management and internal IDs for Attendance/Hosts. Require profiles for hosts. Enforce VK-ID uniqueness and relationship existence transactionally. Preserve self-deletion/self-demotion protections; protect the last administrator. Implement defined profile-deletion behaviour for existing host links.

Keep authorization and mutations in one transaction, serialize VK IDs as strings, and test denied access, overlapping roles, duplicate identities, invalid hosts, deletion and rollback. Use Context7 where applicable. Preserve user edits. Do not deploy, commit or push.
